# 游戏内容分类生成与资产库设计

## 已确认的目标

用户先手动选择“角色、地图、场景、道具”，再生成所选对象的设计内容、Prompt 和图片。资产库按世界项目、类别、内容条目组织，同一条目的设计、Prompt 和图片集中展示。

内测继续使用现有模型与图片服务。质量要求优先：不因本次分类改造缩短用户描述、降低图片分辨率或减少现有审查轮次。不新增请求频率限制或付费服务。

## 生成入口

美术生产页面首先展示四个类别。用户选择类别后，可创建条目或打开已有条目继续制作。文生图工作台沿用当前条目的类别、名称、Prompt 与关联世界；直接进入工作台时也需要选择类别和条目名称。

用户可选择已有世界观作为背景，也可输入独立需求。地图、场景和道具不要求先创建 NPC。世界观确认后由用户选择下一步类别，不再自动限定为创建角色。

同一世界可以有多个角色和其他内容条目。生成新角色不会覆盖旧角色档案。当前选中的角色仍可进入原有角色设计流程。

切换类别或条目时，当前尚未保存的内容保留为该条目的草稿。正在生成的请求绑定发起时的条目，返回结果不能落入后来选中的条目。

## 四类生成要求

所有类别均保留名称、设计说明、所属世界、风格、用户原始要求、中英文 Prompt、反向提示词、构图、色彩、光照和画幅。

| 类别 | 专用设计信息 | Prompt 验收重点 |
| --- | --- | --- |
| 角色 | 身份、玩法职责、外观、服装、行为、随身物件；保留已有 NPC 背景与人格字段 | 身份视觉线索明确，表现符合用户设定；环境不抢占主体 |
| 地图 | 地图尺度、区域、地标、道路与连接、入口出口、功能区、探索或战斗动线、观察视角 | 空间关系和路径清楚；俯视、等距或其他视角按用户选择表达 |
| 场景 | 地点用途、空间布局、建筑或地形、交互点、时间天气、氛围、叙事细节 | 场景空间与功能明确；人物仅在用户需要时作为尺度或活动参照 |
| 道具 | 用途、形制、材质、结构、尺寸、状态、操作方式、所属角色或地点 | 轮廓和功能可辨；展示视角与背景服务于道具设计 |

模型基于选定类别生成专用设计字段和 Prompt。服务端校验类别与结果一致，用户选定的类别不会被模型输出覆盖。未知类别返回清楚的输入错误。

共享世界信息作为设计约束，不逐字堆进每张图的 Prompt。用户明确的身份、用途和视觉要求必须保留；例如“神秘、潜行的黑客”需要能解释其黑客身份的外观与行为，不能仅靠战术装备表达。反向提示词针对当前任务，避免默认禁止用户需要的画风、文字或物件。

地图交付包括设计说明、布局 Prompt 和概念图。图片不承诺精确网格、可验证通行路径或游戏引擎可直接加载的数据。

## 资产库归纳

浏览层级为：世界项目 → 类别 → 内容条目 → 设计 / Prompt / 图片。无世界关联的条目进入“独立素材”，仍可按四类筛选。

资产库提供“全部、角色、地图、场景、道具”筛选，显示各类条目数量。支持按名称、摘要、标签搜索，按最近更新排序，并筛选“仅设计、已有 Prompt、已有图片”的生产状态。

卡片显示条目名称、类别、所属世界、简短摘要、封面、Prompt 和图片数量。图片到期时间继续明确展示；到期图片清理不删除条目设计与 Prompt。

条目详情集中展示设计资料、Prompt 历史和图片历史。每次保存新生成结果创建一条记录，保留原始 Prompt 与模型信息；图片明确关联生成时所用的 Prompt。重新生成不会覆盖旧记录。

摘要和状态从已保存数据生成，不为整理资产额外调用模型。条目名称与标签可修改，用户可手动调整类别和所属世界；分类调整不改写历史 Prompt。角色、地图、场景、道具之间可记录简单关联，例如“破解器属于 Zero”“黑市诊所位于旧城区”。

删除单张图片只删除该图片。删除条目前确认会移除的设计、Prompt 和图片，并沿用现有删除失败重试行为。

## 数据与兼容

统一内容条目至少包含：稳定 ID、类别、名称、摘要、标签、可选世界 ID、世界快照、专用设计资料、关联条目 ID、创建和更新时间。类别内部值为 character、map、scene、prop。

世界项目使用稳定 ID，不能仅以名称区分。改名后归属不变。Prompt 记录和图片记录均携带条目 ID；Prompt 记录保存中文、英文、反向提示词及生成参数快照，图片保存所用 Prompt 记录 ID。

沿用现有 Neon 和 Blob。对现有档案、Prompt 和图片表做兼容扩展，保留旧接口读取能力；新增字段采用默认值或允许为空。迁移可重复执行，不删除旧记录。

已知 NPC 档案归入“角色”。明确的地图、场景和道具标签映射到相应类别。无法可靠判断的旧记录放入“待分类”，供用户修正，不猜测归到角色。

旧本地 Prompt 和当前 NPC 按稳定迁移标识导入，重复执行不产生副本。只有服务器确认成功后才标记迁移完成，失败时保留本地原件并提供重试。旧档案内无法明确归属的 Prompt 保留原关联，标记待整理，不擅自拆散或删除。

## 接口、组件与错误处理

类别定义、专用设计校验和 Prompt 构建放在共享模块中，前端与服务端使用同一类别标识。生成接口接收类别、条目 ID、世界背景和用户需求；成功结果带回条目 ID 和类别。

从现有 App 拆出类别选择、条目编辑、资产库筛选和条目详情组件，范围限于本次流程。保留既有模型设置、内测会话和费用控制入口。

保存失败时保留设计、Prompt 和生成图片，展示可重试错误。重新加载资产库失败不能显示成空库。请求过期或取消后不覆盖当前草稿。服务端继续校验工作区边界，客户端传来的条目 ID 不构成访问授权。

## 验证与交付

覆盖四类从选择、填写、生成 Prompt、生图、保存到重新打开的流程；确认非角色生成不依赖 NPC，并能在同一世界保存多个角色。

重点回归分类与结果不一致、切换条目后迟到的响应、同名条目、保存失败重试、重复迁移、旧数据缺少类别、图片与 Prompt 关联、工作区隔离和图片到期后的档案保留。

以 PDF 中的赛博朋克世界为人工验收例：分别建立主角黑客、Zero、旧城区地图、黑市诊所和破解器。每项独立生成和归档，重新打开后类别、世界关联、Prompt 与图片关系一致。

自动化测试验证数据和请求契约；视觉与语义质量需要使用真实模型进行小规模人工验收。交付时区分已通过的本地测试与尚需部署环境验证的项目。
