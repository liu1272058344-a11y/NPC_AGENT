# 远程图片资产与档案详情设计

## 背景

当前应用把角色档案、Prompt 记录和生成图片的引用保存在浏览器 `localStorage`。这会造成以下问题：

- 图片是否可继续访问取决于上游生成地址的有效期。
- 资产只能在当前浏览器中看到，清理浏览器数据后会丢失。
- “保存成功”只代表本地元数据写入成功，不能证明图片已经持久保存。
- 生成结果没有完整的查看、缩放和下载体验。
- 档案详情不能清晰地在角色信息、Prompt 历史和关联图片之间切换。

本次改动建立一个受容量和保留期限约束的远程资产库。图片文件不写入前端持久存储，也不写入应用服务器本地磁盘。

## 目标

1. 用户保存生成图片后，图片在资产库中可靠出现，并与角色档案和生成 Prompt 关联。
2. 图片存放在远程对象存储中，应用只保留必要的远程引用和元数据。
3. 每个匿名工作区最多保存 20 张图片、总计 100 MB，每张图片默认保留 30 天。
4. 页面持续提示临时保存政策，并显示单张图片的到期时间和当前配额。
5. 用户可以打开图片查看器，缩放、平移、重置和下载原图。
6. 档案详情提供“档案信息”“Prompt 记录”“档案图片”三个独立视图。
7. 到期图片由定时任务删除；用户主动删除图片时立即释放配额。

## 非目标

- 本阶段不建设注册、登录、订阅或付费存储系统。
- 本阶段不承诺永久保存、版本历史、团队共享或跨浏览器身份恢复。
- 本阶段不迁移浏览器中已有但上游地址已经失效的图片。
- 本阶段不把图片二进制、Base64 或 Blob 内容写入 `localStorage`、IndexedDB、项目仓库或应用服务器磁盘。

## 技术选型

### 图片文件

使用 Vercel Blob。保存操作由服务端读取图片生成接口返回的远程文件，并写入 Blob。对象路径使用不可预测的工作区标识、资产标识和随机后缀，避免文件名冲突。

首版使用公共 Blob 的随机 URL，由应用生成下载响应。当前应用没有账号认证；私有 Blob 仍需要应用自行建立访问身份，不能单独解决授权问题。建立账号系统后，可迁移至私有 Blob 和用户级鉴权。

### 元数据

通过 Vercel Marketplace 接入 Neon Postgres。数据库保存工作区、角色档案、Prompt 快照、图片资产、大小、Blob 地址、创建时间和到期时间。

数据库是资产列表、配额统计和关联关系的唯一事实来源。浏览器本地数据只用于匿名工作区 ID 和未提交的表单状态。

### 定时清理

使用 Vercel Cron 每日调用受 `CRON_SECRET` 保护的清理接口。清理任务先查询已过期资产，再删除对应 Blob，最后删除数据库记录。任务必须幂等；对象已不存在时仍可安全完成元数据清理。

## 身份与数据归属

在没有账号系统的阶段，前端首次访问时生成高熵随机 `workspaceId`，保存到 `localStorage`。所有资产 API 都要求工作区 ID，并通过不可预测的资产 ID 访问记录。

该机制提供浏览器级隔离，但不等同于用户认证。清理浏览器数据或更换浏览器后，用户不能找回原工作区。界面需要明确提示这一限制。以后加入登录系统时，通过服务端迁移将 `workspaceId` 关联到用户 ID。

## 数据模型

### `workspaces`

- `id`: 随机工作区 ID，主键。
- `created_at`: 创建时间。
- `last_seen_at`: 最近访问时间。

### `npc_archives`

- `id`: 档案 ID。
- `workspace_id`: 所属工作区。
- `name`: 角色名称。
- `summary`: 卡片摘要。
- `profile_json`: 完整角色档案快照。
- `created_at`、`updated_at`。

### `prompt_records`

- `id`: Prompt 记录 ID。
- `workspace_id`、`archive_id`。
- `prompt`、`negative_prompt`。
- `provider`、`model_id`。
- `created_at`。

### `image_assets`

- `id`: 图片资产 ID。
- `workspace_id`、`archive_id`、`prompt_record_id`。
- `blob_url`、`pathname`。
- `content_type`、`byte_size`、`width`、`height`。
- `provider`、`model_id`。
- `created_at`、`expires_at`。

`workspace_id`、`expires_at` 和关联外键建立索引。所有查询必须同时限定 `workspace_id`。

## API 设计

### `GET /api/assets`

返回当前工作区的档案卡片、图片计数、容量使用量和最近到期时间。支持按档案 ID 获取详情，也支持分页读取图片和 Prompt 历史。

### `POST /api/assets/images`

请求包含档案 ID、Prompt 快照和生成图片源 URL。服务端执行：

1. 校验工作区和请求字段。
2. 获取远程图片，限制响应大小、超时和允许的图片 MIME 类型。
3. 在事务或等价的补偿流程中检查 20 张和 100 MB 配额。
4. 上传至 Vercel Blob。
5. 写入 Prompt 记录和图片元数据。
6. 返回完整资产记录及最新配额。

如果数据库写入失败，服务端删除刚上传的 Blob。只有 Blob 和数据库都成功后，前端才显示“已保存到资产库”。

### `GET /api/assets/images/:id/download`

校验工作区归属后返回下载响应或短期可用的下载地址，文件名包含角色名和生成时间。下载失败时返回可读错误。

### `DELETE /api/assets/images/:id`

校验归属，删除 Blob 和元数据。重复删除返回成功，保证幂等。

### `GET /api/cron/assets-cleanup`

校验 `Authorization: Bearer <CRON_SECRET>`。分批处理到期记录，避免函数超时。每批记录删除结果并允许下次任务继续处理失败项。

## 前端交互

### 生成结果

- 点击图片打开全屏图片查看器。
- 查看器支持滚轮缩放、按钮缩放、拖动平移、重置、下载和 `Esc` 关闭。
- “保存资产”按钮在请求期间禁用并显示进度。
- 保存成功后显示到期日期和最新用量，例如“已保存，29 天后清理 · 3/20 张 · 12/100 MB”。
- 已保存图片显示“已保存到资产库”，避免重复提交。
- 配额不足、上游图片失效、上传失败或数据库失败时显示对应原因。

### 资产库

- 顶部显示图片数量、容量使用量和临时保存提示。
- 卡片封面优先使用该档案最近保存的图片。
- 没有图片时使用当前文字占位封面。
- 点击档案卡片进入档案详情。

### 档案详情

详情页保留返回资产库的入口，并提供三个页签：

1. **档案信息**：显示完整角色字段。
2. **Prompt 记录**：按时间倒序显示 Prompt、反向 Prompt、Provider、Model ID 和生成时间。
3. **档案图片**：网格显示全部关联图片、到期时间和模型；点击进入查看器，并可下载或删除。

页签选择写入 URL 查询参数，刷新后保持当前视图。空状态分别说明没有 Prompt 或没有保存图片。

## 数据迁移与兼容

- 首次加载新资产库时，现有本地 NPC 档案可以提交到远程数据库，使用确定性迁移标识避免重复创建。
- 本地 Prompt 文本可迁移为 Prompt 记录。
- 旧图片条目只有在远程源 URL 仍可读取时才尝试上传；失败条目保留本地提示，告知用户需要重新生成。
- 新接口稳定后停止把图片资产写入 `npc-forge-image-library`。完成一次迁移后删除该键。

## 容量与保留策略

- 单工作区图片上限：20 张。
- 单工作区总容量上限：100 MB。
- 单张图片默认保留：30 天。
- 到期时间以服务端写入时间计算，不能由客户端修改。
- 配额检查以数据库聚合结果为准。
- 接近限制时（达到数量或容量的 80%）显示提醒。
- 资产不会因为被查看或下载而自动续期。

## 错误处理

- 所有 API 返回统一结构：`{ ok, data?, error?: { code, message } }`。
- 预期错误使用稳定代码，例如 `QUOTA_COUNT_EXCEEDED`、`QUOTA_BYTES_EXCEEDED`、`SOURCE_EXPIRED`、`ASSET_NOT_FOUND`。
- 前端保留当前生成结果，保存失败不会清空图片或 Prompt。
- 删除 Blob 成功而数据库删除失败时，清理任务可以根据残留记录再次处理。
- 数据库不可用时资产库显示重试入口，不把空响应误报为“没有资产”。

## 安全边界

- 服务端只接受 `http`/`https` 图片源，并校验 Content-Type、最大响应体和超时。
- 获取外部 URL 时阻止 localhost、环回地址、私网地址和云元数据地址，降低 SSRF 风险。
- 不向客户端暴露 `BLOB_READ_WRITE_TOKEN`、数据库凭据或 `CRON_SECRET`。
- 输出文件名做字符清理，响应设置安全的 Content-Disposition 和 Content-Type。
- 首版匿名工作区只适用于原型数据，不用于敏感或受监管内容。

## 测试与验收

### 单元测试

- 配额计算、到期日期和 80% 提醒。
- 资产详情分组和页签路由。
- API 错误到中文提示的映射。
- 图片查看器缩放范围、重置和键盘行为。

### API 测试

- 保存成功、重复保存、源地址失效、超时和超限。
- Blob 成功但数据库失败时执行补偿删除。
- 工作区隔离和越权访问拒绝。
- 删除和定时清理的幂等性。

### 端到端验收

1. 生成图片并保存后，资产库立即显示该图片。
2. 刷新页面后图片和档案仍存在。
3. 打开图片可缩放、平移、重置和下载。
4. 档案详情可在三个页签间切换，内容关联正确。
5. 第 21 张或超过 100 MB 时保存被拒绝并显示清晰提示。
6. 到期记录经清理任务处理后，Blob 和数据库记录均消失。
7. 构建、现有单元测试和新增测试全部通过。

## 部署配置

Vercel 项目需要配置：

- `BLOB_READ_WRITE_TOKEN`
- Neon 提供的数据库连接变量
- `CRON_SECRET`

`vercel.json` 增加每日一次的清理任务。部署前执行数据库迁移，部署后通过生产环境完成一次上传、列表、下载和删除冒烟测试。

## 发布顺序

1. 建立 Blob、数据库和环境变量。
2. 部署数据库结构和只读资产 API。
3. 部署图片保存、下载和删除 API。
4. 接入前端资产库和图片查看器。
5. 执行本地数据迁移并停止新的本地图片记录。
6. 启用每日清理任务。
7. 完成生产环境验收。
