# 可反复编辑的世界观与角色档案设计

## 背景

当前创建流程把“Agent 已生成完整结果”近似当成“用户已确认”，并通过 `phase` 将用户从世界观阶段推进到角色阶段。世界观只能作为当前会话状态存在，无法作为独立档案保存；角色生成后也缺少清晰的补充、修改和重新设定入口。

本次改造把世界观和角色都视为可持续编辑的内容档案。Agent 负责提出草案和按要求修订，阶段切换只由用户的明确操作触发。

## 目标

- 世界观可以在没有角色的情况下独立保存、打开和继续编辑。
- 用户可以对当前世界观或角色反复补充、局部修改、直接编辑字段或重新生成。
- Agent 返回完整结果后停留在当前内容类型，不自动切换阶段。
- 用户只有点击明确的导航操作时才进入角色设计或返回世界观。
- 同一档案的修改覆盖最新内容；新建或另存为产生新的档案。
- 角色记录所属世界观，但删除世界观不会级联删除角色。

## 非目标

- 不为同一档案保存历史版本或提供版本回滚。
- 不改造图片、Prompt 和其他资产的现有版本策略。
- 不根据名称判断两个档案是否相同。
- 不自动合并两个不同档案。

## 核心模型

### 档案身份

世界观和角色均使用创建时生成、之后保持不变的 UUID 作为档案 ID。名称只是可编辑字段，不能参与档案去重。

- 修改、补充、直接编辑或重新生成当前档案：保留 ID，更新该档案。
- “新建世界观”“新建角色”：生成新 ID 和空白编辑状态。
- “另存为新世界”“另存为新角色”：复制当前内容并生成新 ID。
- 同名档案可以共存。

### 世界观档案

世界观档案包含现有 `WorldProfile` 字段，并增加稳定 ID、档案类型、更新时间和编辑状态所需元数据。资产库将其识别为独立的 `world` 分类。

### 角色档案

角色档案保留现有 `NPC` 字段和稳定 ID，并以可空的 `worldId` 关联世界观。角色保存自己的必要世界背景快照，确保所属世界被删除后仍可阅读和继续编辑。

## 用户流程

### 世界观工作区

1. 用户新建世界观并输入需求。
2. Agent 返回问题或世界观草案，界面始终停留在世界观工作区。
3. 草案出现后，用户可以：
   - 输入补充或修改要求；
   - 直接编辑世界观字段；
   - 基于当前要求重新生成；
   - 保存当前档案；
   - 另存为新世界；
   - 主动进入角色设计。
4. 保存后再次修改会把档案标记为“有未保存更改”，直到再次保存。

### 角色工作区

1. 用户从某个世界观进入角色设计，或直接新建独立角色。
2. Agent 返回问题或角色草案，界面始终停留在当前角色。
3. 用户可以补充、局部修改、直接编辑字段、重新生成或保存。
4. “新建角色”创建不同 ID；“另存为新角色”复制当前内容并创建不同 ID。
5. “返回世界观”只改变当前编辑视图，不删除或覆盖角色。

### 明确的阶段控制

`world_ready` 和 `complete` 仅表示本轮生成结果完整，不再具有导航含义。以下操作是唯一的工作区切换入口：

- “进入角色设计”
- “返回世界观”
- 从资产库打开世界观或角色
- 新建世界观或新建角色

Agent 的追问、用户的自由输入和快速回答均不能隐式切换内容类型。

## Agent 修订语义

每次请求必须携带以下上下文：当前内容类型、当前档案 ID、当前档案完整内容、对话记录和用户本轮要求。

服务端指令要求模型：

- 将“增加、修改、删除、改成、补充”等表述应用到当前档案；
- 未被用户要求修改的字段必须保留；
- “重新生成”仍保留档案 ID，但允许重写全部内容；
- 不得自行切换到其他内容类型；
- 信息不足时可以追问，但追问仍属于当前档案。

客户端继续对返回结构做完整校验，只有校验通过的结果才替换编辑区草案。请求失败时保留用户当前内容和未保存状态。

## 保存与数据流

世界观和角色统一通过远程档案接口保存：

1. 编辑器创建稳定档案 ID。
2. 用户触发保存时，客户端提交档案 ID、类型、完整最新内容及关联 ID。
3. 服务端按 `workspaceId + archiveId` 执行 upsert。
4. 同一 ID 的再次保存更新原记录，不增加档案数量。
5. 新 ID 创建新记录。
6. 资产库重新加载后显示最新内容。

本地 `npc-forge-*` 数据继续用于兼容迁移，不改变键名；新流程以远程档案为主。本地恢复数据时必须保持稳定 ID，避免刷新后重复创建。

## 资产库

资产库增加“世界观”分类，并继续支持角色、地图、场景、道具和未分类内容。

- 世界观卡片显示名称、类型、时代、摘要和关联角色数量。
- 角色卡片显示名称、定位和所属世界；关联世界不存在时显示“独立角色”。
- 打开卡片进入对应编辑工作区，并加载最新档案内容。
- 删除世界观前提示其关联角色数量。
- 确认删除世界观后，只删除世界观档案；关联角色的 `worldId` 置空并保留世界背景快照。
- 删除角色不影响世界观。

## 编辑状态与冲突

编辑器区分三种状态：未保存草稿、已保存、存在未保存更改。用户离开有未保存更改的档案前显示确认提示。

内测阶段仍采用最后一次保存覆盖的策略，不增加多人协作锁。服务端保存响应返回最新 `updatedAt`；客户端以响应内容更新当前状态。网络失败不得清空草稿。

## UI 调整

- 将现有“先构思世界，再创建 NPC”的强制向导改为“世界观 / 角色”可切换工作区。
- 世界观结果区增加：编辑字段、继续补充、重新生成、保存档案、另存为新世界、进入角色设计。
- 角色结果区增加：编辑字段、继续补充、重新生成、保存档案、另存为新角色、返回世界观、新建角色。
- 生成按钮文案区分“生成草案”“应用修改”“重新生成”。
- 状态标签使用“未保存草稿”“已保存”“有未保存更改”，不再用“待确认”暗示线性流程。
- 资产库筛选增加“世界观”。

## 兼容性与迁移

- 已保存的旧 NPC 继续按角色档案显示。
- 旧的当前世界观首次保存时分配稳定世界观 ID。
- 旧角色没有 `worldId` 时保留原有 `world` 文本并显示为独立角色。
- 不重命名现有浏览器存储键，避免用户数据丢失。
- 现有图片与 Prompt 关联不因本次改造而改变。

## 测试策略

### 状态与交互

- 完整世界观返回后仍停留在世界观工作区。
- 完整角色返回后仍停留在当前角色工作区。
- 补充信息携带当前档案并保持未修改字段。
- 只有明确按钮可以切换工作区。
- 返回世界观不会删除角色。

### 保存

- 同一世界观 ID 多次保存后资产库只有一个档案并显示最新内容。
- 同一角色 ID 多次保存后资产库只有一个档案并显示最新内容。
- 新建和另存为会生成不同 ID，即使名称相同也能共存。
- 世界观可以在没有角色时保存、打开和继续编辑。
- 刷新后打开档案可以继续编辑而不生成重复记录。

### 关联与删除

- 一个世界观可以关联多个独立角色档案。
- 删除世界观不会删除角色；角色转为独立状态并保留可读快照。
- 删除角色不影响所属世界观。

### 回归

- 原有 Prompt、图片生成、资产保存、内测登录和额度功能保持通过。
- 旧本地世界观与角色可以迁移和打开。

## 完成标准

- 用户可以独立保存至少两个不同世界观，并分别创建多个角色。
- 对任一档案反复修改和保存不会增加重复档案。
- Agent 在没有用户明确操作时不会推进到下一工作区。
- 世界观与角色都可以从资产库重新打开、修改和保存。
- 删除关联内容时不会发生隐式级联数据丢失。
- 全量自动化测试、类型检查和生产构建通过。
