# 游戏内容档案与美术生产连续性设计

日期：2026-10-03
状态：流程方向已确认；书面规格待审阅

## 目标与已确认要求
本工具用于游戏内容生产。世界构建、角色/场景/地图/道具设计、美术简报、Prompt 与图片必须围绕可追溯的内容档案持续深化。角色可以是人、动物、植物、石头或机械。用户可以直接输入或修改图片提示词，无须经过系统 Prompt 工程。

## 当前代码证据与限制
src/types/npc.ts 的 WorldProfile 只有基础世界概述，NPC 强制包含 speechStyle 等字段，ArtAssetPrompt 缺少来源条目与世界版本。src/agents/visualAgent.mjs 默认补服装和装备，存在人形假设。src/agent/npcCreator.ts 已传递 world/contentProfile，但数据契约不足。src/App.tsx 已支持手动提示词生图，保存图片时却优先使用当前 npc.id，可能错误关联。
截图中“未命名草稿”和条目类型编辑界面在当前工作区未找到。实施前必须定位对应分支或实际运行版本；不得将截图中控件的推测行为当作已验证实现。

## 方案选择
推荐共通档案加类型扩展：共通部分提供身份、世界关联、用途、关系、视觉简报及版本；各类型独立补充必要字段。
仅修改 Prompt 无法解决来源与持久化问题。统一巨型表单会迫使所有对象填写无关字段，因此不采用。

## 数据与关联
世界档案具有稳定 ID、版本、现有世界字段与视觉方向（风格、色彩、材质、生态和视觉禁忌）。
内容条目具有稳定 ID、kind（character/scene/map/prop）、name、worldId（独立素材可为空）、版本、游戏用途、描述、关联条目、视觉简报及来源。
角色的实体类别与游戏身份分别记录。按用途提供外形、行为、交互、表达方式和玩家关系；不强制语言、服装或武器。场景记录空间、氛围与玩法；地图记录尺度、区域、连接和导航；道具记录功能、材质、使用规则及状态。
字段区分已确认、待完善与用户覆盖。模型建议不自动等同于已确认事实。档案全面意味着覆盖生产所需信息，无关字段不必填写。
Prompt 版本保存来源条目、世界版本、简报版本、实际文本、负向文本与生成方式。图片记录实际提交的提示词、提供商、模型、生成参数和可选来源关联。

## 世界构建流程
保留世界先行流程。世界确认后可选择创建任一内容类型，不强制先生成 NPC。提供基于已有世界的针对性引导，只询问缺失且影响当前任务的信息；可跳过未必需的信息。内容确认后可生成初始美术简报与中英文 Prompt，并进入美术生产继续完善。

## 美术生产流程
选择条目后自动载入其世界、玩法用途、关系和视觉简报，展示继承来源与待完善项。新增生产要求包括构图、镜头、光照、输出用途与规格。用户可覆盖继承信息；与世界约束冲突时给出可操作提示，并允许作为明确的版本覆盖保存，不静默改写原世界设定。
世界或条目更新后标记旧 Prompt 来源已变化。重新生成由用户主动触发，旧版本保留。

## 自由生图流程
文生图工作台可独立进入。支持带入系统 Prompt、修改带入文本、完全手写三种使用方式；不要求优化、不强制世界或条目、不自动追加风格约束。生成请求使用界面实际文本及模型支持的参数。
保存图片时明确选择关联条目或独立素材，不能因当前存在 NPC 而自动绑定。修改带入的提示词保留来源但标记用户编辑；纯手写默认独立。生成完成后保存其请求快照，避免用户修改输入框后将错误文本记到旧图片上。

## 草稿与命名
空白编辑状态按类型显示“新地图（未保存）”等标签，不把占位文案当作真实名称或已保存档案。条目名称可直接编辑；保存需要非空名称，并有清晰提示，保留已填内容。保存成功后选择器立即显示真实名称。已保存条目提供重命名入口，更新名称不改变 ID、图片关系和历史。
新建与切换条目时对未保存修改提供保留/放弃/取消选择。可重复命名，以稳定 ID 区分。现有真实未命名记录仍可打开并补名，不批量虚构名称。

## 持久化与兼容
先检查实际运行版本、现有存储和 API 再确定数据库增量迁移。旧 NPC 转为 character，保留原 ID 与旧字段；缺失类别标记未确定。旧 Prompt 保留原文本，仅对可证实的关系建立关联；无法确认来源的记录标为未关联。旧数据不能因为新类型字段缺失而被拒绝或丢弃。
沿用现有图片容量和保留期限。此改动不含部署、不改变已有存储配额。

## 边界与职责
数据契约及兼容转换独立于 UI。上下文组装负责世界与条目继承，Prompt 生成负责按实体类型生成视觉要求，图片生成负责提交用户实际输入，档案服务负责保存来源、版本及关联。避免继续将所有逻辑集中增加到 App.tsx。

## 失败处理
生成失败保留输入与已确认档案；保存失败不显示成功或丢失草稿。无法解析生成结果时提示重试，不以默认人物经历或装备填补。过期来源可提示重新生成，但不阻断自由生图。

## 验收
1. 同一世界下的场景、地图、道具、非人角色生成均携带世界与对应条目上下文。
2. 树、石头和动物按自身用途生成，不被自动添加人类服装、语言或武器。
3. 手写提示词无须生成系统 Prompt 即可生图；最终提交文本与保存的请求快照一致。
4. 独立图片不会误挂当前 NPC；关联图片刷新后仍能追溯来源。
5. 世界变更可识别旧 Prompt，但不会覆盖历史或用户文本。
6. 草稿命名、保存、重命名与切换的行为清晰且不会丢数据。
7. 旧 NPC、Prompt 和图片可继续读取；现有回归检查通过。
针对数据契约、上下文传递、非人角色、请求快照、关联与兼容迁移编写有意义测试，并验证构建和关键 UI 流程。
