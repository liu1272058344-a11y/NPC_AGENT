# 对话式游戏内容构建与档案归类规格

日期：2026-10-03。基线：master 14ca00d。用户已确认对话式构建方向，并要求规划档案页面归类；本文待审阅后编写实施计划。

## 用户目标

用户只需表达游戏想法或内容需求，AI 继承已确认设定，提出有用的问题并生成设计与视觉 Prompt。用户无需懂 Prompt 工程、先命名、填写多份重复表单。界面减轻拥挤，正式档案、草稿和图片成果可明确找到。

## 页面职责与导航

合并游戏设定和世界构建为“游戏内容构建”，接纳游戏玩法、世界观和具体内容设计。旧 Game Design/World Builder 内部入口映射至新页，保留游戏设定 Pipeline 输出及旧世界/NPC 数据。项目总览更新流程说明。

游戏内容工作室改为成果整理页面，展示已有内容与草稿，继续设计进入对应的构建对话；不再提供第二套长表单。资产库承接同一档案浏览器的完整视图，二者使用相同归类和详情逻辑，不维护两套记录。文生图仅编辑提示词、生成和保存；保持原文交接及请求快照。

## 构建对话

初次进入显示简短引导和单一输入框，用户可描述一个游戏想法。AI 引导确定玩法用途、世界规则和视觉方向；足够时直接生成，不强制从头回答固定问卷。现有 Pipeline 的一键完整生成作为次要选项保留，结果进入同一成果预览，不能启动重复模型调用。

已有世界显示当前世界摘要，“设计内容”菜单包含角色、地图、场景、道具、服饰；世界观作为可继续编辑的上下文。选择类型直接开始该类对话，不跳到手动字段表单。每个内容稳定 ID 绑定独立会话与世界 ID；可单独创作，不强制关联世界。角色可以是人、动物、树、石头或机械。

首条消息可用自然语言，例如“设计一棵能保存记忆的古树”。不要求先填名称，AI 在生成结果中建议名称，用户保存前可修改。模型需返回简短面向用户的设计说明或关键问题，以及结构化结果；结构化 JSON 不直接充当聊天回复。

不足以决定主体、用途、布局或视觉方向时，一轮最多询问 2—3 个关键问题，提供选择和自由输入；允许用户说“你来建议”，建议清楚标为 AI 建议，不冒充用户事实。不重复询问已确认内容，不默认添加人类服装或武器。

连续对话携带真实消息历史、当前设计、世界与视觉简报；用户说“更古老一点”“不要武器”时修改相关内容，其他确认资料保留。源设定有变化时提示，不自动覆盖旧 Prompt。每轮有明确处理中/失败/完成状态，失败保留输入和此前结果，可重试；重试不重复追加同一用户消息，不让过期请求写入其他会话。

对话和草案本地保存并可恢复，保存档案时附对话来源与设计版本。旧档案没有历史对话时显示已有资料，并从继续设计开始新对话，不伪造旧对话。切换有编辑或处理中内容时保护状态，可保留、取消；生成与保存结果必须使用对应会话的 ID 与请求快照。

## 页面布局

桌面主区域为对话与固定在会话底部的输入区，旁边为结果预览；窄屏按对话、结果顺序展示。当前世界为紧凑上下文条，不默认展开长段资料。

生成结果默认展示名称、设计摘要和当前视觉 Prompt。中文/生图文本切换预览，字段编辑、标签、反向提示词、世界来源与覆盖要求置于可展开的“详细资料”。主操作只保留继续对话、保存档案、一键用于文生图；类型选择集中在“设计内容”菜单。

全局输入控件使用一致的深色背景、文字、边框、焦点状态及足够留白，修复当前白色文本框。按钮区可换行且有间距，避免挤成多行无层级按钮。没有结果时隐藏不可用结果操作，不堆空白 Prompt 文本框。

## 档案归类与浏览

一级浏览区域为“内容档案”“图片素材”“草稿”。正式保存记录与本地未保存会话明确区分，草稿不会伪装成已保存档案。不同浏览区域只是同一数据的视图，不复制记录。

内容档案以世界观、角色、地图、场景、道具、服饰为类型。提供所属世界筛选（全部、指定世界、暂不关联世界）、搜索、最近更新时间与生产状态筛选（仅设计、已有 Prompt、已有图片）。全部视图显示世界与内容卡片，但类型计数、搜索和筛选一致；不用“待分类”作为所有自由图片的主入口。

图片素材默认按图片展示，可按所属档案、世界和类型筛选。关联图片显示来源名称，点击查看图片及实际使用的 Prompt；没有关联内容的纯手写图片显示“独立图片”，不要求创建内容类型。若一份独立图片记录有多张图片，各图仍只保存一次，以图片 ID 展示；来源未知的旧记录进入“待整理”，保留现有 ID 和历史，用户可明确分类或关联。

草稿显示可恢复的世界/内容会话与有实际内容的旧草稿。未命名项显示“角色草稿 · 最近内容摘要”等可辨认标签，而不是一串“未命名草稿”。空白旧草稿不占主要列表，不自动删除存储。打开草稿恢复对应世界、类型、消息和结果；保存后该记录归入正式档案，本地未保存修改仍清楚标记。

### 档案详情

顶部显示名称、类型、所属世界和保存状态；主操作为“继续设计”，有可用 Prompt 时提供“一键用于文生图”。重命名、调整类型/世界、标签和关联条目放在“管理档案”；删除操作远离主操作，并沿用现有确认。

详情按“设计资料”“Prompt 版本”“图片”三个区域切换；对话来源作为设计资料的可展开记录，避免历史和长表单同时铺满一页。世界详情显示玩法/世界规则/视觉方向及关联内容入口；旧 NPC 详情保留原背景、目标、人格和行为资料，不能只显示空 design.fields。

Prompt 版本保留原文本、生成时的世界与条目版本、编辑方式；可以带入选定的历史文本，不自动用最新文本替换。图片显示实际请求及对应版本。图片到期依现有策略提示，Prompt 和设计仍保留。

同名内容依稳定 ID 区分，世界删除或读取失败时明确提示来源失效，不伪称独立或丢资料；用户仍可继续对话和自由生图，重新保存关联需明确选择有效世界。类别修改不改变 ID 或既有图片关系。

## 实现边界与兼容

沿用现有生成路由、鉴权、资产库和存储额度；为内容生成增量增加消息历史、当前设计和用户回复字段，旧单次 requirements 请求继续兼容。名称不再是开始对话的前置条件，正式保存仍要求非空名称。新增 UI 对话/档案视图组件与会话辅助模块，避免继续扩展 App 的重复页面。

旧 Game Design Pipeline、世界档案、NPC、内容草稿、Prompt 和图片均可读取。没有可证明的类型、世界或对话不编造；AI 建议与已确认信息区分。需要存储元数据时使用既有 JSON 字段，经 API 校验和测试，不新建并行数据库。

此轮实现不自动推送或部署，不改变模型计费、存储期限或权限，不引入批量生成和自动删除功能。

## 验收

1. 游戏设定与世界构建只有一个“游戏内容构建”入口，旧流程资料仍可继续使用。
2. 用户选择类型后只需自然语言对话，无须先命名或手写 Prompt；AI 继承世界，针对缺口提问并产生设计与视觉 Prompt。
3. 多轮修改保留确认资料，失败重试与会话切换不丢消息、结果或归属；旧档案续写不伪造历史。
4. 桌面和窄屏对话与预览清楚，文本框统一深色，主要按钮不拥挤，详情默认折叠。
5. 档案可按六种内容类型、所属世界、状态和搜索查找；独立图片、待整理记录和草稿各有明确入口，不出现大量同名占位项。
6. 旧 NPC 字段、世界关联内容、Prompt 版本和图片实际请求可以追溯；所有分类与编辑保留稳定 ID。
7. 一键用于文生图保持原文、允许编辑、保护既有输入及图片结果。完整串行测试、构建、lint 和主要浏览器流程验证，明确模拟与生产验证范围。

## 自审

对话设计与档案归类覆盖用户新增要求；工作室与资产库复用一个浏览器，防止再次增加重复入口。独立图片是浏览归类，不强行改变原始内容类别。世界构建原有世界存储与内容档案服务分别沿用，详情统一展示，旧数据无须强行转换。类型选择、保存归属与图片请求均在明确阶段处理。
