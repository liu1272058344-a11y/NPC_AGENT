# NPC Forge AI：生成与评审 Agent 工作流设计

## 目标

在现有 NPC Forge AI 两阶段创建流程的后端增加内部评审环节，让世界观和 NPC 档案在返回前经过结构化质量检查与有限次数自动修订，减少空泛、遗漏和世界观不一致的问题。评审机制属于内部实现，不向用户暴露。

## 用户流程

```text
用户描述
  ↓
世界观构思 Agent
  ↓
世界观评审 Agent
  ↓
自动修订（最多 2 次）
  ↓
用户确认世界观
  ↓
NPC 创建 Agent
  ↓
NPC 评审 Agent
  ↓
自动修订（最多 2 次）
  ↓
保存并展示 NPC 档案
```

用户仍在 NPC Creation 页面完成全部流程，不新增独立页面。前端只显示统一的“正在生成”状态，不显示评审 Agent、评分、问题列表、修订次数或内部提示词。评审失败时，后端返回可重试错误，不把未经评审的草稿标记为完成。

## Agent 职责

### 生成 Agent

- 世界观 Agent：收集类型、时代、氛围、核心规则和主要冲突，生成 `WorldProfile`。
- NPC Agent：基于已确认世界观，收集 NPC 用途、玩家关系、核心目标和角色冲突，生成 `NPC`。

### 评审 Agent

评审 Agent 只负责检查和提出可执行修改，不负责重新设计流程。输出固定 JSON：

```json
{
  "approved": false,
  "issues": ["背景没有解释角色与玩家相遇的原因"],
  "suggestions": ["补充角色过去经历，并说明该经历如何导致当前任务"],
  "score": 72
}
```

世界观评审标准：完整性、内部一致性、独特性、可用于游戏的冲突、与用户原始意图的一致性。

NPC 评审标准：世界观一致性、角色动机、背景具体度、玩家关系、玩法功能、性格与行为规则可执行性、避免模板化。

## API 与数据流

保留现有 `/api/npc` 作为前端唯一入口。评审与修订请求只在后端内部发起，前端请求仍只携带：

- `phase`: `world` 或 `npc`
- `messages`: 当前对话
- `world`: 已确认世界观（NPC 阶段）
- `model`: 用户选择的模型

后端内部维护 `draft`、`review` 和 `revisionCount`。前端只收到现有的 `needs_clarification`、`world_ready` 或 `complete` 结果。主 Agent 和评审 Agent 使用同一个用户选择的模型与 API 配置，API Key 不写入项目或 localStorage。

## 状态机

- `world_collecting`：收集世界观信息
- `world_reviewing`：后端内部评审世界观，不暴露给前端
- `world_ready`：评审通过后，返回世界观并等待用户确认
- `npc_collecting`：收集 NPC 信息
- `npc_reviewing`：后端内部评审 NPC 档案，不暴露给前端
- `complete`：评审通过后，返回并保存最终档案
- `error`：调用失败，前端保留对话并允许重试

任何评审最多自动修订 2 次。达到上限仍未通过时，后端返回明确的可重试错误，不向前端发送评审详情或低质量草稿。

## 前端交互

- 对话区只显示统一的“思考中”状态。
- 世界观卡片只展示通过后端评审的世界观结果。
- NPC 档案只在后端评审通过后标记为“已保存”。
- 后端评审失败时不清空前端对话。
- 用户点击现有“重试”按钮即可重新执行生成与内部评审。

## 验证标准

1. 世界观只有通过后端评审后才能返回 `world_ready`。
2. NPC 只有通过后端评审后才能返回 `complete`。
3. 评审最多触发两次自动修订，不会无限循环。
4. 后端评审建议会被注入下一次内部修订请求。
5. 直接模型模式和本地后端模式使用同一套状态结构。
6. 模型返回异常 JSON 时不会造成 React 崩溃。
7. 用“末日废土药房前急救员”场景跑通世界观 → 后端评审 → 用户确认 → NPC → 后端评审 → 保存全流程。
