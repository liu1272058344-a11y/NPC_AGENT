# NPC Forge AI：生成与评审 Agent 工作流设计

## 目标

在现有 NPC Forge AI 两阶段创建流程上增加独立评审环节，让世界观和 NPC 档案在展示给用户前经过结构化质量检查与有限次数自动修订，减少空泛、遗漏和世界观不一致的问题。

## 用户流程

```text
用户描述
  ↓
世界观构思 Agent
  ↓
世界观评审 Agent
  ↓
自动修订（最多 2 次）
  ↓
用户确认世界观
  ↓
NPC 创建 Agent
  ↓
NPC 评审 Agent
  ↓
自动修订（最多 2 次）
  ↓
保存并展示 NPC 档案
```

用户仍在 NPC Creation 页面完成全部流程，不新增独立页面。评审期间页面显示当前阶段和处理中状态；评审失败时保留原始生成结果并提供重试，不阻塞用户继续操作。

## Agent 职责

### 生成 Agent

- 世界观 Agent：收集类型、时代、氛围、核心规则和主要冲突，生成 `WorldProfile`。
- NPC Agent：基于已确认世界观，收集 NPC 用途、玩家关系、核心目标和角色冲突，生成 `NPC`。

### 评审 Agent

评审 Agent 只负责检查和提出可执行修改，不负责重新设计流程。输出固定 JSON：

```json
{
  "approved": false,
  "issues": ["背景没有解释角色与玩家相遇的原因"],
  "suggestions": ["补充角色过去经历，并说明该经历如何导致当前任务"],
  "score": 72
}
```

世界观评审标准：完整性、内部一致性、独特性、可用于游戏的冲突、与用户原始意图的一致性。

NPC 评审标准：世界观一致性、角色动机、背景具体度、玩家关系、玩法功能、性格与行为规则可执行性、避免模板化。

## API 与数据流

新增一个统一的工作流入口，保留现有 `/api/npc` 兼容性。工作流请求携带：

- `phase`: `world` 或 `npc`
- `action`: `generate`、`review` 或 `revise`
- `messages`: 当前对话
- `world`: 已确认世界观（NPC 阶段）
- `draft`: 待评审的生成结果
- `review`: 最近一次评审结果（修订时）

返回值包含 `status`、`phase`、`draft`、`review` 和 `revisionCount`。主 Agent 和评审 Agent 使用同一个用户选择的模型与 API 配置，API Key 不写入项目或 localStorage。

## 状态机

- `world_collecting`：收集世界观信息
- `world_reviewing`：评审世界观
- `world_ready`：评审通过或达到修订上限，等待用户确认
- `npc_collecting`：收集 NPC 信息
- `npc_reviewing`：评审 NPC 档案
- `complete`：评审通过或达到修订上限，展示并保存档案
- `error`：调用失败，保留草稿并允许重试

任何评审最多自动修订 2 次。达到上限后不再循环调用，向用户展示当前结果和评审建议。

## 前端交互

- 对话区显示“生成中”“评审中”“正在根据评审优化”等状态。
- 世界观卡片增加评审状态、评分和简短建议。
- NPC 档案只在评审结束后标记为“已保存”。
- 评审失败不清空对话或草稿。
- 用户可点击“重试评审”，不必重新输入全部内容。

## 验证标准

1. 世界观生成后必定经过评审或明确显示评审失败。
2. NPC 生成后必定经过评审或明确显示评审失败。
3. 评审最多触发两次自动修订，不会无限循环。
4. 评审建议能影响下一次修订请求。
5. 直接模型模式和本地后端模式使用同一套状态结构。
6. 模型返回异常 JSON 时不会造成 React 崩溃。
7. 用“末日废土药房前急救员”场景跑通世界观 → 确认 → NPC → 评审 → 保存全流程。
